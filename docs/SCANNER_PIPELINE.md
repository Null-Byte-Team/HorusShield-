# V-8 Scanner Pipeline

V-8 Scanner is an orchestration layer over three established, independently-maintained security tools. **HorusShield does not implement its own vulnerability-detection or exploit logic anywhere in this pipeline** — every actual test request sent to a target is generated and controlled by OWASP ZAP, Nikto, or Nmap themselves. This is a deliberate architectural boundary (see `backend/vscanner/__init__.py`'s module docstring and `CONTRIBUTING.md`), not an accident of scope.

## Pipeline

```
POST /api/vscanner/scan/start
  {target_url, tools: [nmap, zap, nikto], active_scan: bool, authorized_confirmation: bool}
        |
        v
routes_vscanner.py: _validate_target_url()
  - real urllib.parse + hostname-format validation, rejects malformed input
  - if active_scan=true, requires authorized_confirmation=true or the
    request is rejected with 400 before anything runs
        |
        v
VScannerManager.start_scan()  (vscanner/orchestrator.py)
  - one background thread per scan; only one scan runs at a time
        |
        +- 1. Nmap (nmap_runner.py)
        |      -sV --script default,safe   (NOT the 'vuln'/'exploit' NSE categories)
        |      Parses Nmap's own XML output for open ports/services
        |
        +- 2. OWASP ZAP (zap_client.py) -- REST calls to a ZAP daemon
        |      a. new_session()
        |      b. spider()          -- crawls the target, discovers URLs
        |      c. passive_scan_wait() -- waits for ZAP's non-intrusive passive analysis
        |      d. active_scan()     -- ONLY if active_scan=true was explicitly set;
        |                             this is what actually sends live test requests,
        |                             and it's ZAP's own scan engine doing it
        |      e. get_alerts()      -- retrieve ZAP's own findings
        |
        +- 3. Nikto (nikto_runner.py)
        |      Standard Nikto web-server misconfiguration/exposure scan,
        |      JSON output parsed as-is
        |
        +- 4. AI Cortex (ai/vscanner_cortex.py) -- see docs/AI_PIPELINE.md
               normalize -> deduplicate -> classify (OWASP/CWE) -> correlate ->
               confidence-score -> prioritize -> explain
        |
        v
Persisted: vscans / vscan_findings / vscan_reports tables
        |
        v
Report Generator (services/vscan_report_generator.py) -> PDF / HTML / JSON
```

## Safety Controls, Concretely

- **Active scan is opt-in, not default.** `config.VSCAN_ALLOW_ACTIVE_SCAN_DEFAULT = False`. The API rejects `active_scan: true` unless `authorized_confirmation: true` is also sent, and the frontend requires an explicit confirmation dialog before setting either flag.
- **Nmap never runs `vuln`/`exploit` NSE script categories** — only `default,safe`, which are informational/banner-grabbing scripts, not attack scripts.
- **A missing tool doesn't fail the whole scan.** If Nikto, Nmap, or ZAP is unavailable, that stage logs a specific warning (`vscan_log` Socket.IO event) and the scan continues with whatever tools *are* available. ZAP is started automatically only when a launcher is discovered and `HORUS_ZAP_AUTOSTART=true`.
- **Only one scan runs at a time** (`VScannerManager._active_scan_id` lock), which limits both resource use and the blast radius of a misconfigured target.

## What Actually Gets Tested Where

| Tool | What it checks | Intrusive? |
|---|---|---|
| Nmap | Open ports, service/version fingerprinting | No — connects to ports, doesn't send exploit payloads |
| ZAP spider + passive scan | Crawls the site, analyzes traffic already generated by the crawl for issues (headers, cookies, etc.) | No |
| ZAP active scan | Sends ZAP's own test payloads (SQLi/XSS/etc. probes) to found endpoints | **Yes — opt-in only** |
| Nikto | ~6700 known misconfigurations/dangerous files/outdated software signatures | Mostly no — mostly GET requests to known paths, not exploitation |

## Known Gaps (see final audit report for full list)

- No automated tests exist for `vscanner/orchestrator.py`, `zap_client.py`, `nikto_runner.py`, `nmap_runner.py` — they require the real external tools/daemon, which aren't available in CI. Testing them meaningfully would need either the real binaries in the CI image or a mocked ZAP daemon.
- `/api/vscanner/*` requires authentication (`analyst_required` for start/stop/delete, `login_required` for read endpoints) — see `docs/SECURITY_ARCHITECTURE.md`. This was a real gap in an earlier version of HorusShield (anyone who could reach the API could start a scan against any target) and is now fixed and verified live via `scripts/smoke_test_auth.py`.
